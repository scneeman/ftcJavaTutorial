Stage 1: Java Basics, Syntax & Math Foundations

1. Keywords vs. Identifiers

Programming languages enforce strict structural rules. Every token in Java belongs to a category:

  • Keywords: Pre-defined, reserved words built into Java that have specific functional meaning. They are always lowercase (e.g., public, class, void, if, while, double). You cannot name variables or methods after keywords.
  • Identifiers: Custom names given by programmers to identify classes, variables, methods, and constants (e.g., armMotor, targetPosition). Java enforces camelCase by convention: variable names start lowercase (drivePower), while Class names start uppercase (LinearOpMode).

2. Access Modifiers & Scope

Access modifiers define where variables and methods can be accessed across your robot's codebase:

  • public: Visible to all classes across the entire project.
  • private: Accessible only within the class where it is declared. In FTC, we use private variables inside OpModes to prevent external code from accidentally modifying motor states.
  • protected: Accessible within the same package or subclasses.

3. Primitive Data Types vs. Reference Types

Java is a strongly typed language—every variable must be explicitly declared with its data type before use:

// Primitive Types: Hold simple values directly in memory
double motorPower = 0.75;       // Decimal values (-1.0 to 1.0 for power, distances)
int targetEncoderTicks = 1440;   // Whole numbers (encoder counts, state steps)
boolean isLimitSwitchPressed = false; // True/False states (sensor triggers, toggle flags)

// Reference Types: Point to objects stored elsewhere in memory
String driverMessage = "Autonomous Active"; // Text strings

4. Basic Math Operations & Pitfalls in Java

Robotics code relies heavily on math to scale joystick inputs, convert encoder ticks to inches, and compute sensor thresholds.

Arithmetic Operators

  • Addition (+): e.g., targetTicks + 500
  • Subtraction (-): e.g., currentPos - startPos
  • Multiplication (*): e.g., joystickY * 0.8 (scaling motor power to 80%)
  • Division (/): Behaviour depends on data types!
  • Modulus (%): Returns the remainder of division. Frequently used for cycling through autonomous states or checking even/odd loop counts.

CRITICAL FTC PITFALL: Integer Division vs. Double Division

If you divide two integers in Java, Java drops the fractional decimal part completely (it truncates, not rounds)!

// BAD: Both numbers are integers!
double gearRatio = 1 / 2;  // Result is 0.0, NOT 0.5!

// GOOD: At least one operand must be a floating-point double
double gearRatio = 1.0 / 2.0; // Result is 0.5
double power = encoderTicks / 1440.0; // Dividing by double preserves decimals

Compound Operators & Shortcuts

autoStep++;          // Equivalent to autoStep = autoStep + 1; (Increment)
autoStep--;          // Equivalent to autoStep = autoStep - 1; (Decrement)
armPower *= 0.5;     // Equivalent to armPower = armPower * 0.5; (Cut power in half)
encoderTarget += 100; // Add 100 ticks to current target

Operator Precedence (PEMDAS)

Java follows standard mathematical order of operations (Parentheses, Multiplication/Division, Addition/Subtraction). Always use parentheses to ensure correct motor scaling:

// Calculate arcade drive power: (Drive + Turn) scaled by half
double leftPower = (driveInput + turnInput) * 0.5;

5. Control Flow & Boolean Logic

Robots make decisions using comparison operators (==, !=, >, <, >=, <=) and logical operators (&& AND, || OR, ! NOT):

// Decision making in TeleOp or Autonomous
if (armEncoder > 2000 && !isLimitSwitchPressed) {
    armMotor.setPower(0.0); // Emergency stop arm if over-extended
} else {
    armMotor.setPower(0.5);
}

Stage 2: Object-Oriented Programming (OOP) in FTC

In FTC, Java classes act as structural blueprints, and physical devices are controlled by instantiating objects built from those blueprints.

1. Classes vs. Objects

  • Class: The master template (e.g., DcMotor, Servo, IMU).
  • Object: A concrete instance created in memory (e.g., frontLeftMotor, wristServo).

2. Methods and Dot Notation

Methods are functional actions an object performs. You invoke methods using dot notation: objectName.methodName(parameters);

3. Packages & Import Statements

To use hardware devices, you must import the corresponding FIRST Tech Challenge library files at the top of your Java file:

package org.firstinspires.ftc.teamcode;

// Import FIRST SDK Hardware classes
import com.qualcomm.robotcore.hardware.DcMotor;
import com.qualcomm.robotcore.hardware.Servo;

public class MechanismControl {
    private DcMotor armMotor;
    private Servo clawServo;

    public void setClawPosition(double position) {
        clawServo.setPosition(position); // Passing argument 'position' to method
    }
}

Stage 3: FTC SDK Architecture

FTC OpModes execute code in two main structures depending on whether you are running Autonomous or TeleOp routines.

LinearOpMode vs. Iterative OpMode

  • LinearOpMode: Executes sequentially line-by-line. Standard for Autonomous. Pauses execution at waitForStart() until the driver presses PLAY.
  • OpMode (Iterative): Event-driven execution. Standard for TeleOp. Contains routines like init(), init_loop(), start(), and a continuously repeating loop().

Hardware Mapping & Gamepad Inputs

The hardwareMap connects configured string names on the Driver Station to code variables. Inputs from controllers are continuously read during the loop:

@TeleOp(name = "Standard Drive", group = "TeleOp")
public class StandardDrive extends LinearOpMode {

    // Declare hardware objects
    private DcMotor leftDrive;
    private DcMotor rightDrive;

    @Override
    public void runOpMode() {
        // Hardware Mapping (Matches Driver Station Robot Configuration)
        leftDrive  = hardwareMap.get(DcMotor.class, "left_drive");
        rightDrive = hardwareMap.get(DcMotor.class, "right_drive");

        telemetry.addData("Status", "Initialized");
        telemetry.update();

        // Wait for driver to press PLAY
        waitForStart();

        // Main OpMode loop
        while (opModeIsActive()) {
            // Gamepad joystick Y values are inverted (-1.0 is full UP)
            double drivePower = -gamepad1.left_stick_y;
            
            leftDrive.setPower(drivePower);
            rightDrive.setPower(drivePower);

            telemetry.addData("Power", drivePower);
            telemetry.update();
        }
    }
}
