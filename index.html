Stage 1: In-Depth Java Syntax, Keywords & Math

1. Categorization of Reserved Java Keywords

Java has 50+ reserved keywords that have fixed, built-in definitions. You cannot use these as variable or class names. Here are the core keyword categories used daily in FTC robotics:

Category Keywords FTC Robotics Application
Access Modifiers public, private, protected Control code visibility. private protects hardware variables inside OpModes; public exposes class methods.
Data Types double, int, boolean, void Specify data stored in memory. void indicates a method performs actions without returning a value.
Control Flow if, else, while, for, switch, case Make decisions based on sensor inputs or loop through autonomous state machines.
Class & Structural class, extends, import, package, new Define class structures, inherit FTC SDK functionality, and instantiate hardware objects.

2. Essential Java & FTC Helper Methods

Beyond keywords, FTC programmers rely heavily on standard Java library methods and FTC SDK telemetry tools:

Class / Library Common Method Robot Purpose
Math Math.abs(val) Ignores signs to compute absolute distance or deadband joystick noise.
Math Math.toRadians(deg) Converts heading degrees from IMU sensor into radians needed by Pedro Pathing.
Math Math.max(a, b) / Math.min(a, b) Clips drivetrain motor power outputs so values never exceed 1.0 or -1.0.
telemetry telemetry.addData("Key", val) Sends diagnostic telemetry data from the robot to the Driver Station screen.
telemetry telemetry.update() Flushes the data buffer to display immediate live updates on the Driver Station.

3. Basic Math Operations & Integer Division Pitfalls

Java supports standard arithmetic (+, -, *, /, %). However, **Integer Division** is a frequent source of bugs for beginners:

// INCORRECT: Dividing two integers drops the decimal completely!
double armPower = 1 / 2;  // Results in 0.0, NOT 0.5!

// CORRECT: Ensure at least one value is explicitly a double
double armPower = 1.0 / 2.0; // Results in 0.5
double tickRatio = currentTicks / 1440.0; // Preserves floating-point decimals

Configuring Motors in Java

package org.firstinspires.ftc.teamcode;

import com.qualcomm.robotcore.hardware.DcMotor;
import com.qualcomm.robotcore.hardware.DcMotorSimple;

public class SubsystemExample {
    private DcMotor armMotor;

    public void configureArm(DcMotor motorFromMap) {
        armMotor = motorFromMap;
        
        // Reverse direction if mechanical gearing flips movement
        armMotor.setDirection(DcMotorSimple.Direction.REVERSE);
        
        // Reset encoder tick counter to 0
        armMotor.setMode(DcMotor.RunMode.STOP_AND_RESET_ENCODER);
        
        // Set motor to run using raw power control
        armMotor.setMode(DcMotor.RunMode.RUN_WITHOUT_ENCODER);
    }
}

Stage 3: The FTC Iterative `OpMode` Lifecycle

Your team is using the **Iterative `OpMode`** structure for both TeleOp and Autonomous. Unlike `LinearOpMode`, an `OpMode` is event-driven and runs continuously inside built-in loop routines (~50–100 times per second).

The 4 Core Life-Cycle Methods

  • init(): Runs once when the driver hits INIT on the Driver Station. Use this to hardware map motors, set directions, and initialize sensors.
  • init_loop(): Loops continuously while waiting for the driver to press PLAY. Great for updating vision processing or selecting autonomous paths.
  • start(): Runs once when the driver presses the PLAY button.
  • loop(): Loops continuously after PLAY is pressed until the match timer runs out or STOP is pressed. This is where gamepad reading and state machine execution happen.

Complete Iterative `OpMode` Template

package org.firstinspires.ftc.teamcode;

import com.qualcomm.robotcore.eventloop.opmode.OpMode;
import com.qualcomm.robotcore.eventloop.opmode.TeleOp;
import com.qualcomm.robotcore.hardware.DcMotor;

@TeleOp(name = "Iterative TeleOp", group = "TeleOp")
public class IterativeRobot extends OpMode {

    private DcMotor leftDrive;
    private DcMotor rightDrive;

    @Override
    public void init() {
        // Hardware Mapping (Matches Control Hub config name)
        leftDrive  = hardwareMap.get(DcMotor.class, "left_drive");
        rightDrive = hardwareMap.get(DcMotor.class, "right_drive");

        telemetry.addData("Status", "Initialized & Ready!");
    }

    @Override
    public void init_loop() {
        // Runs repeatedly between INIT and PLAY
        telemetry.addData("Status", "Waiting for driver to press PLAY...");
    }

    @Override
    public void start() {
        // Reset timers or encoders once match begins
        telemetry.addData("Status", "Match Started!");
    }

    @Override
    public void loop() {
        // Gamepad joysticks return inverted Y (-1.0 is full UP)
        double drivePower = -gamepad1.left_stick_y;
        
        leftDrive.setPower(drivePower);
        rightDrive.setPower(drivePower);

        telemetry.addData("Drive Power", drivePower);
    }
}
