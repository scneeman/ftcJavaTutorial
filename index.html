Stage 1: In-Depth Java Syntax, Keywords & Math

1. Java Reserved Keywords vs. Programmer Identifiers

When writing Java code for FTC, every word in your program falls into one of two fundamental categories:

  • Java Reserved Words (Keywords): Words built directly into Java (such as public, class, double, or void). They are protected by the compiler and cannot be used as custom variable names.
  • Programmer-Defined Identifiers: Custom names created by you (e.g., leftFrontMotor, armTargetPosition). They should follow Java camelCase naming conventions.
Key Takeaway: Compiler errors often occur when students accidentally name variables using reserved words or forget that Java is case-sensitive (e.g., double vs. Double).

2. Anatomic Breakdown of a Java Method Header

A Method Header tells Java how a function can be accessed, what it calculates, what name it has, and what input values it needs to run. Let's break down this FTC arm control method word-by-word:

public void liftArm(double targetPower, int targetTicks)
1. public (Access Modifier) Specifies visibility. public means other classes (like your main OpMode) can call and execute this method.
2. void (Return Type) Specifies output. void means this method executes actions (moving a motor) but returns no data back. If it returned a number, this would say double or int.
3. liftArm (Method Name) A programmer-chosen identifier following camelCase naming conventions. Describes the action performed.
4. (double targetPower, int targetTicks) (Parameters) Input variables required to run:
  • double targetPower: Floating-point number for motor power (e.g., 0.75).
  • int targetTicks: Whole integer for target encoder position (e.g., 1200).

5. Basic Math Operations & Integer Division Pitfalls

Java supports standard arithmetic (+, -, *, /, %). However, **Integer Division** is a frequent source of bugs for beginners:

// INCORRECT: Dividing two integers drops the decimal completely!
double armPower = 1 / 2;  // Results in 0.0, NOT 0.5!

// CORRECT: Ensure at least one value is explicitly a double
double armPower = 1.0 / 2.0; // Results in 0.5
double tickRatio = currentTicks / 1440.0; // Preserves floating-point decimals

Configuring Motors in Java

package org.firstinspires.ftc.teamcode;

import com.qualcomm.robotcore.hardware.DcMotor;
import com.qualcomm.robotcore.hardware.DcMotorSimple;

public class SubsystemExample {
    private DcMotor armMotor;

    public void configureArm(DcMotor motorFromMap) {
        armMotor = motorFromMap;
        
        // Reverse direction if mechanical gearing flips movement
        armMotor.setDirection(DcMotorSimple.Direction.REVERSE);
        
        // Reset encoder tick counter to 0
        armMotor.setMode(DcMotor.RunMode.STOP_AND_RESET_ENCODER);
        
        // Set motor to run using raw power control
        armMotor.setMode(DcMotor.RunMode.RUN_WITHOUT_ENCODER);
    }
}

Stage 3: The FTC Iterative `OpMode` Lifecycle

In FTC Java, an **Iterative `OpMode`** is event-driven and runs continuously inside built-in loop routines (~50–100 times per second).

The Core Life-Cycle Methods

  • init(): Runs once when the driver hits INIT on the Driver Station. Use this to hardware map motors, set directions, and initialize sensors.
  • start(): Runs once when the driver presses the PLAY button. Use this to reset encoders or start timers right as the match begins.
  • loop(): Loops continuously after PLAY is pressed until the match timer runs out or STOP is pressed. This is where gamepad readings and motor updates occur.

Complete Iterative `OpMode` Template

package org.firstinspires.ftc.teamcode;

import com.qualcomm.robotcore.eventloop.opmode.OpMode;
import com.qualcomm.robotcore.eventloop.opmode.TeleOp;
import com.qualcomm.robotcore.hardware.DcMotor;

@TeleOp(name = "Iterative TeleOp", group = "TeleOp")
public class IterativeRobot extends OpMode {

    private DcMotor leftDrive;
    private DcMotor rightDrive;

    @Override
    public void init() {
        // Hardware Mapping (Matches Control Hub config name)
        leftDrive  = hardwareMap.get(DcMotor.class, "left_drive");
        rightDrive = hardwareMap.get(DcMotor.class, "right_drive");

        telemetry.addData("Status", "Initialized & Ready!");
    }

    @Override
    public void start() {
        // Reset timers or encoders once match begins
        telemetry.addData("Status", "Match Started!");
    }

    @Override
    public void loop() {
        // Gamepad joysticks return inverted Y (-1.0 is full UP)
        double drivePower = -gamepad1.left_stick_y;
        
        leftDrive.setPower(drivePower);
        rightDrive.setPower(drivePower);

        telemetry.addData("Drive Power", drivePower);
    }
}
